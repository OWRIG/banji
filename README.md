# 磐石 Panshi

一个给**不懂技术的 AI 协作者**用的项目模板：前端、后端、数据库已经打通，工程上的决定已经做好。你只需要跟 AI 讲清楚业务需求。

## 为什么有这个模板

现在各个部门都开始用 AI 自己开发内部系统。写代码这件事，AI 已经能做得不错；但从动手之前到开发过程中，每个项目都要面对大量**工程决策**：

- 用什么框架、什么数据库？
- 代码放在哪里、怎么组织？
- 前端和后端怎么对接？用户填的数据怎么校验？
- 改完之后，怎么知道有没有把别的地方改坏？
- 表结构变了，已经存下来的数据怎么办？

没有工程经验，这些问题很难判断，AI 每次给的答案也不一样。结果往往是：每个项目长得都不一样，能跑，但说不清稳不稳；出了问题，别人也很难接手。

**磐石的做法，是把这些工程决策提前做好、固定下来**，让 AI 协作者不需要在缺少工程背景的情况下自己做判断：

- **一个能直接运行的项目模板**：前端、后端、数据库已经打通，带一个完整的示例功能。
- **一份写给 AI 的规则（[AGENTS.md](AGENTS.md)）**：在这个项目里该怎么写、不能做什么、怎样才算做完。
- **几个常见任务的技能（[.agents/skills/](.agents/skills/)）**：新增功能、修改表结构、加登录，每个都带验证过的参考代码。

磐石不重新发明东西。用到的都是社区主流、维护活跃的开源方案，模板只负责把它们用推荐的方式组合好。

### 设计原则

1. **不让使用者做技术决策**：技术栈只有一套，初始化时不需要选任何东西。
2. **完成要能自动验证**：`pnpm check` 一条命令检查类型、代码规范和测试，AI 必须跑通才算做完。
3. **给 AI 能照着写的样板**：自带的示例功能和 skill 里的参考代码都经过验证，AI 模仿现有代码比读文档可靠得多。
4. **默认带齐，不用就删**：前端、后端、数据库默认都有；删除比添加更不容易出错。只有登录是按需添加的。

## 适用范围

✅ **适合**：demo、原型、内部系统（用户不多，部署在一台机器上）。

⚠️ **出现以下情况，说明项目已经超出了模板的设计范围**，建议找研发团队评审架构（例如把 SQLite 换成 PostgreSQL）：

- 需要部署多份，或者要求服务不能中断
- 同时写数据的人很多，或者数据量明显变大
- 要给公司外部的人用，或者涉及敏感数据
- 已经成为关键业务，需要多人长期维护

AI 在开发过程中发现这些情况，也会主动提醒你。

## 快速开始

先安装 [Node.js](https://nodejs.org)（22.12 或更高版本）和 [pnpm](https://pnpm.io)，然后在项目目录里运行：

```bash
pnpm install
pnpm dev
```

打开终端里打印的地址（通常是 http://127.0.0.1:5173）就能看到页面。第一次启动会自动创建数据库，不需要任何配置。

然后用 Codex（或其他支持 AGENTS.md 的 AI 编程工具）打开这个目录，直接说你想做什么，例如：

> 做一个客户台账：记录客户名称、联系人、电话和备注，可以搜索、编辑和删除。

## 常用命令

| 命令 | 作用 |
|---|---|
| `pnpm dev` | 启动开发环境 |
| `pnpm check` | 完整检查（类型、代码规范、测试） |
| `pnpm fix` | 自动修复格式问题 |
| `pnpm db:generate` | 修改数据表定义后，生成迁移文件 |
| `pnpm db:migrate` | 把数据库升级到最新结构 |
| `pnpm db:backup` | 备份数据库到 `data/backups/` |
| `pnpm db:studio` | 在浏览器里查看和编辑数据 |
| `pnpm build` | 打包 |
| `pnpm start` | 上线运行 |

## 技术栈

| 用途 | 选型 | 为什么 |
|---|---|---|
| 前端 | React + TypeScript + Vite | 最主流，AI 最熟悉 |
| 页面路由 | TanStack Router | 链接写错了能在检查时发现 |
| 请求数据 | TanStack Query + Hono RPC | 前端直接拿到后端接口的类型，对接不会对错字段 |
| 界面 | shadcn/ui + Tailwind CSS | 组件代码在项目里，想改随时能改 |
| 后端 | Hono | 轻量，和前端共享类型 |
| 数据库 | SQLite + Drizzle | 一个文件就是整个数据库，零安装；表结构改动有迁移记录 |
| 校验 | zod | 同一份规则，前端提交前和后端接收时都用 |
| 检查 | TypeScript + Biome + Vitest | 合成一条 `pnpm check` |

## 目录结构

```
├── AGENTS.md          给 AI 的规则
├── .agents/skills/    给 AI 的任务技能（新增功能、修改表结构、加登录）
├── src/
│   ├── shared/        前后端共用的校验规则
│   ├── server/        后端：接口、数据库
│   └── web/           前端：页面、组件
├── drizzle/           数据库迁移记录
└── data/              数据库文件和备份（不提交到 git）
```

## 上线运行

在服务器上：

```bash
pnpm install
pnpm build
pnpm start
```

- 一个进程同时提供页面和接口，默认端口 3000（在 `.env` 里设置 `PORT` 可修改，参考 `.env.example`）。
- 所有数据都在 `data/app.db` 这一个文件里。**`data/` 目录要放在不会被清空的磁盘上**，并定期运行 `pnpm db:backup`（或直接备份整个 `data/` 目录）。
- 每次启动会自动把数据库升级到最新结构。
- 加了登录功能的项目，还需要在 `.env` 里设置 `BETTER_AUTH_SECRET` 和 `BETTER_AUTH_URL`，没设置时服务会拒绝启动并提示。

## 常见问题

**同时开发多个项目？** 前端端口被占用时会自动换一个（5174、5175……），以终端打印的地址为准。后端默认都用 3000 端口，同时运行多个项目时，在每个项目的 `.env` 里设置不同的 `PORT`，否则后启动的项目会连到先启动的项目的后端。

**想直接看数据库里的数据？** 运行 `pnpm db:studio`。

**`pnpm install` 时提示 better-sqlite3 相关的错误？** 它需要为当前电脑下载对应的数据库驱动。确认 Node.js 版本不低于 22.12，然后删除 `node_modules` 重新安装。
